## GettingScienceDone facts admitted

- `run-experiment.yaml` implements CONFIRMATORY / EXPLORATORY / REPLICATION execution.
- Gates include power analysis, temporal-integrity/HARKing prevention, red-team, data-contract, and drift checks.
- `negative-results.yaml` implements `NULL_RESULT`, `UNDERPOWERED`, and `TRUE_NEGATIVE`; its underpowered edge case forbids promoting low-power non-rejection to `TRUE_NEGATIVE`.
- The specs tree also contains ablation, claim/output audit, prompt creation, data contract, export, FAIR check, experiment discovery, and handoff contracts.

## Antigence facts admitted

Architecture in current README includes orchestrator/T-helper, B-cell pattern memory, NK negative selection, dendritic feature/context processing, memory retrieval, killer validation, and regulatory calibration. It supports offline operation, API/MCP, domain packs, continuous training data, and an LLM-assisted prompt-injection lane.

`BENCHMARKS.md` reports:
- synthetic Python 40: NegSl-AIS acc .675 / precision 1.0 / recall .35; B-cell acc .583 / recall 1.0;
- curated Python 60: B-cell and GuardrailPipeline acc .75 / precision 1.0 / recall .50 / reported FPR 0;
- Devign test subset: NegSl .495, B-cell .515, Guardrail .505 with high FPR; repository conclusion is approximately chance for semantic C/C++ vulnerability detection.

The repository proposes embeddings (CodeBERT/VulBERTa/local Ollama), language-specific extractors, and larger training as follow-up. Those are proposals, not executed results in this appendix.
