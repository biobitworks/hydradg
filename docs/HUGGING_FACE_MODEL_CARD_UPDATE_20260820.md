### FCO/FCG interpretation

The fractal design is recursive custody rather than a decorative naming convention. A source can be hashed into an FCO; evidence derived from it can become another FCO; KnowledgeAtoms, SeedsOfTruth, StateSnapshots, experiment receipts, hosted migration receipts, model artifacts, conversation packages, and releases can each be independent FCOs. Their governed relationships form FCG snapshots with declared roots. A lower-level root can be referenced inside a higher-level custody object, so provenance, context, and governance repeat across scales.

Hash identity does not establish correctness. A graph/root does not imply signing or Merkle commitment.
