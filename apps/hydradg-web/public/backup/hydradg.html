See what changed. Trace why. Test the repair.

HydraDG uses HydraDB to represent changing memory, identity and dependency state as typed graph relationships. FCO/FCG keeps the evidence route behind each derived state so a change can be inspected rather than silently overwritten.

This static artifact is a presentation fallback. It does not claim that local-only HydraDB controls are running in this browser.

01 / GOLDEN PATH

Reference → poison → antidote.

The simplest HydraDG question is: when one load-bearing fact changes, can we show the first divergence, preserve the old state, and verify whether a repair restores the declared current state?

Reference

Read the current state.

A fact is connected to the session/evidence that supports it.

Poison

Change one fact.

The old fact remains. HydraDB can preserve SUPERSEDED_BY and CONTRADICTS relationships rather than flattening history.

Antidote

Restore without erasing.

The valid state is restored as a new state while the perturbation remains inspectable in the history.
